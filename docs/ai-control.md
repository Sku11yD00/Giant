# Driving the editor with AI

Everything the editor can do is a command (AGENTS.md rule 7). The same
commands are available to people (menus and panels), to C# scripts, to the
built-in assistant (later), and to outside AI tools through MCP.

## Connect Claude Code

The editor is an MCP server on stdin/stdout when started with `--mcp`.
Claude Code starts it for you. On Windows, from the folder that holds
`giant_editor.exe`:

```
claude mcp add giant -- giant_editor.exe --mcp
```

Or put this in a `.mcp.json` next to your project (use the full path to the
exe):

```json
{
  "mcpServers": {
    "giant": { "command": "C:/Giant/giant_editor.exe", "args": ["--mcp"] }
  }
}
```

The editor window opens when Claude Code connects and closes when it
disconnects. Ask things like "make the background a sunset orange" or "what
GPU is the editor using?" or "build a small village with a church and light it
like late afternoon"; Claude calls the tools, looks at the result with
`capture_screenshot`, and can undo what it did.

## Commands so far

| Command | Changes things | What it does |
| --- | --- | --- |
| `get_engine_info` | no | Version, graphics backend and GPU, validation layer, frames, frame times over the last 240 frames (average, median, 99th percentile, worst, hitches: frames 1.5x the median and 2 ms over it, and `recent_ms`, the times oldest first, with `recorded`, the count ever; wall clock), `gpu`: the GPU's own time for the newest finished frame (`frame_ms`) and per pass (`passes`: `name` and `ms`, from GPU timestamps; passes run twice, such as culling, are added up; 0 ms on the null backend), window size. With `phases_since` (a `recorded` count), `frame_times.phases`: where the main thread's time went in the frames from then on (the last 240 at most): `typical`, each phase's median ms, and `typical_cpu_ms`, the main thread's CPU time; `slow`, each frame over `phases_over_ms` (default 25) with its `frame`, `ms`, `cpu_ms` and `phases` (those of 0.05 ms or more). The phases: `events`, `mcp` (a screenshot's frame too), `scripts`, `ui`, `weather`, `physics`, `animation` (skinned entities' clips and poses), `begin_frame`, `terrain`, `far_ground`, `scatter`, `scene`, `render` (its parts `render/cells` to `render/shading`), `ui_draw`, `end_frame`, `streaming`, `tail` (the loop's end: the log's report, pacing on the null device), `other`. The gates print, for a flight's hitches, the phase most over its typical time and how long the thread was stalled (neither working nor waiting on the GPU) |
| `get_log` | no | Newest log lines, filtered by level |
| `create_entity`, `create_entities` | yes, undoable | Adds shapes (cube, sphere, plane), imported meshes (`mesh`: a glTF/GLB path), kit placements (`kit`: a kit's name) cloth (`shape: cloth` with `cloth` settings: `width`, `height` in metres, `pin` `top`, `corners` or `left`, `weight` kg/m², `stiffness` 0 to 1; it hangs from the entity's origin in its x-y plane, its scale unused) or decals (`shape: decal` with `decal` settings: stamp shape `disc`, `rectangle`, `ring`, `splat` or `cracks`, opacity, softness, seed) with position, rotation, scale and material; `swing` (`on`, `length` to the pivot above, `hinge` `free` or `x`, `weight` kg, `limit` degrees) makes a cube, sphere, plane, mesh or kit swing in the wind like a lantern or a sign; many in one step |

| `set_kit_breakable` | yes, undoable | `name`, `breakable`, and optionally `strength` (N·s; 0 or left out: 1500): whether simulating lets the kit's placements break. A breakable kit's piece comes loose when hit harder than its strength (a contact, or `impact`), and every piece that stood only on it comes loose too; each falls as its own body. Stopping simulating, or editing the placement, mends it; the scene never changes. Saved with the kit |
| `delete_kit` | yes, undoable | Removes a kit nothing places |
| `list_kits`, `get_kit` | no | Kits with piece and placement counts; one kit's pieces |
| `set_entity` | yes, undoable | Changes any fields of one entity. `body`: how it collides, `fixed` (default), `dynamic` (falls while simulating) or `none`; `mass` in kg (0: from its size); `surface`: what bullets meet, `standard` (default), `flesh`, `wood`, `glass`, `dirt`, `foliage`, `brick`, `concrete` or `metal` (saved with the material; a kit's pieces keep their entities' surfaces); `sway` (0 to 4: bends in the wind from its origin, its foot; 1 a tree, 2 to 3 grass) and `flutter` (0 to 4: its tips shake, leaves), also on kit pieces and scatter items; `maps`: image files drawn over the uvs of built-in shapes and of meshes whose file has them (`list_meshes`: `uvs`) (`base_color`, `normal`, `roughness_metal` (glTF metallic-roughness: G, B), `occlusion` (R), `normal_green_down` for DirectX normal maps; "" removes one; a missing file is refused; an image inside a glTF is `"file.glb#image2"`, its file checked and a missing image reported when cooked, `get_textures`), cooked in the background, also on kit pieces and scatter items. Giving a new `mesh` takes the file's look (`import_mesh`: `material`) under the look fields given with it (base colour, roughness, metallic, emissive, maps), also for `create_entity` and scatter items |
| `delete_entities` | yes, undoable | Removes entities by id |
| `get_entity`, `list_entities` | no | Reads entities (outliner order); `get_entity` adds `simulated` (position, rotation) while simulating has moved one |
| `get_lighting`, `set_lighting` | `set` is undoable | Sun height and direction, sun, sky and ground light, exposure |
| `get_clear_color`, `set_clear_color` | `set` is undoable | The sky colour, which is also the background |
| `new_scene`, `load_scene` | yes, undoable | Empties the scene, or loads a `.scene.json` file |
| `save_scene` | writes a file | Saves the scene as JSON text (meshes by path) |
| `save_world` | writes files | Saves the open world (`world.json` and each 64 m cell file whose entities or terrain tile changed; a cell's file holds its tile, which streams with it; the far ground's chunks over changed tiles are written too, `chunks_written`), or with `folder` and no world open makes a new world there from the scene and opens it |
| `open_world` | yes, undoable | Opens a world folder: the scene becomes the world, cells near the camera load in the background and far ones unload (only when they hold no unsaved edits). Refused while the open world has unsaved edits unless `discard_unsaved` |
| `close_world` | not undoable | Stops streaming; the scene stays as it is, as a plain scene |
| `get_world`, `set_world_streaming` | view only, not undoable | Streaming progress (`open`, `active`: the scene is the world's, `folder`, `cells` with a file, `loaded`, `reading`, `waiting`, `failed`, `unsaved_cells`, `unsaved_settings` (lighting, kits, scatter or weather differ from world.json; `open_world` refuses to drop them too), `entities`, `entities_loaded`, `entities_unloaded`, `ids_changed`: entities given a new id because theirs was taken, `ground`: cells whose file holds a terrain tile, `tiles_loaded`, `tiles_unloaded`, `far_ground`: by level 1 (512 m chunks) and 2 (4096 m) the chunk `files`, `loaded`, `meshes`, `building` and `drawn`, and `hidden` level-1 chunks under a drawing level-2 one, `reading`, `failed`) and `streaming` settings (`load_radius` in metres, default 1536, at most 8192; `unload_margin`, default 128; `entities_per_frame`, default 4096; `reads_in_flight`, default 16; `unload_every` frames, default 30; `unloads_per_frame` cells, default 128; `far_radius_1`, default 8192, and `far_radius_2`, default 32768: how far the far ground's chunks load; `far_radius_used` gives both as used, level 1 at least `load_radius` + 5800) |
| `create_terrain` | yes, undoable | Ground tiles for every 64 m cell the area `from`-`to` (x, z metres) touches: flat at `height` or rolling `hills` (`base`, `amplitude`, `size`, `octaves`, `seed`); `samples` per tile side (8 to 128, default 64: 1 m apart) changes only with no terrain (in a streamed world whose files hold tiles, it is theirs); at most 4096 tiles a command |
| `remove_terrain` | yes, undoable | Removes the tiles an area touches, or `all` (in a streamed world, the tiles loaded; an area with ground saved but not loaded is refused) |
| `set_terrain_heights` | yes, undoable | One tile's `samples` x `samples` heights, rows along +x from the cell's corner, rows going +z |
| `sculpt_terrain` | yes, undoable | A round brush along a stroke of `points` ([x, z]; a dab at least every quarter `radius`): `op` raise or lower (`strength` metres a dab at the centre), smooth or flatten (towards `height`; `strength` 0 to 1), fading over the outer `falloff` of the radius; only existing tiles change (ground of an open world not loaded yet is left as it is: `cells_not_loaded`); at most 4096 cells, 65536 dabs and 16.7 million heights reached a call; `continues`: the first point was the last call's last dab. Returns `dabs`, `tiles_changed`, `heights`. Calls in one merge group (the viewport brush's drag) are one undo step |
| `import_height_map` | yes, undoable | Ground from a `.r16`/`.raw` (16-bit little-endian, square) or `.pgm` (P5 or P2, 8 or 16 bit) file over [`from`, `to`] (the first sample at `from`), black at `low`, white at `high` metres; tiles for every cell the area touches, at the terrain's spacing |
| `add_scatter_layer` | yes, undoable | A layer of things strewn over the ground by rules: `items` (shape, `mesh` or `kit`; `weight`, `scale` [min, max], `align` 0 upright to 1 along the slope, `sink`, material with `maps` as on entities; `tree` {`trunk_radius`, `height`, `strength`} or null: a tree that topples when struck while simulating), points about `spacing` metres apart (a jittered grid; `jitter`), kept by `density`, clumps (`clump_size`, `clumping`), `area` {from, to}, `height_min`/`max` and `slope_min`/`max` (degrees); `seed`, `visible`. Placed on a worker, cell by cell, again where the ground or the layer changes (not saved: worked out from the rules) |
| `set_scatter_layer` | yes, undoable | Changes a layer by `name`: only the fields given (`items` replaces the list, `area` null for everywhere, `new_name`) |
| `remove_scatter_layer` | yes, undoable | Removes a layer by `name`, and what it placed |
| `get_scatter` | read-only | The layers (every field, `points` each) and `cells`, `points`, `instances` (what they draw), `building` (0 when all are placed), `cells_cut_short` |
| `set_weather` | yes, undoable | The scene's weather: an atmosphere the sun shines through, clouds that drift on the wind and shade the ground, height fog. From `preset` (`clear`, `fair`, `cloudy`, `overcast`, `rain`, `storm`, `snow`, `blizzard`, `fog`) if given, else the weather now, then the fields given: `cloud_cover`, `cloud_density` (0 to 1), `cloud_base` and `cloud_thickness` (metres), `cloud_scale` (1: about 3 km clouds), `wind_direction_degrees` (where it blows to, 0 north, 90 east), `wind_speed` (m/s), `fog_density` (1: 150 m mostly hidden), `fog_height` (metres it thins by half), `haze` (default 1), `precipitation` (how hard it rains or snows), `temperature` (degrees C: snow at -1 and below, rain at 2 and above, sleet between; warm melts snow), `wetness` and `snow_cover` (0 to 1: the one given puts the ground there now, the other stays as it is, or from no weather starts at the weather's start value; they are also how a new scene starts, so a preset's alone leave the ground as it is; it then wets, dries, snows over and thaws as time passes). `over_seconds` blends the view over that long from what shows (from no weather: at once; the scene saves the end) |
| `simulate` | view only, not undoable | `on`: starts or stops simulating physics, like a play button. | `step_physics` | view only, not undoable | While simulating, `seconds` of time now (fixed 1/60 s steps, up to 60 s), whatever the frame rate; returns `get_physics` and `stepped`. A minute can take up to about a second in a big world |
| `get_physics` | read-only | `simulating`, `bodies`, `active` (awake), `steps`, `dropped_steps`, `last_step_ms` (CPU), `entity_bodies`, `dynamic_bodies`, `ground_tiles`, `not_colliding` (meshes, decals, body `none`), `refused`, `waiting` entities and `ground_waiting` tiles (bodies follow the scene a share each frame), `moved` (entities simulating has moved), `broken_kits` (placements broken now), `loose_pieces` (falling as bodies), `rubble` (loose pieces come down with no body: far off, or past the cap), `trees` {`trunks` standing as bodies near the camera, `waiting`, `falling` (moving), `fallen`, `laid` (fallen with no body: laid down far off), `refused`, `shrugged` (blows past what may fall at once)}, `ground` {`dents` pressed in while simulating, `tiles` dented, `game` tiles of a loaded game's ground}, `kept` {the scene's kept damage: `cells`, `kits`, `pieces`, `trees`; `game`, the same of a game's damage shown over it; and applied now: `pieces_down`, `trees_down`}, `dust` {`puffs` in the air, `emitted`, `merged` (swelled a young puff), `dropped`} |
| `impact` | view only, not undoable | While simulating, a blow at `point` (metres, world) over `radius` (metres, at most 1000) with `impulse` (N·s, at most 1e9; all three required): each standing piece of a breakable kit within the radius takes the impulse, less toward the edge (`impulse × (1 − distance/radius)`), and comes loose, pushed away from the point, when that is at least its kit's strength; what stood only on it falls with it. Loose pieces within 600 m of the camera fall as bodies (4096 at most); farther, or past the cap, they come down at once as rubble, flat on what is under them. Trees whose trunk has no body (beyond about 400 m, the blow's cells given to the forest first) are laid down at once, their tops on the ground. | `keep_damage` | undoable | Makes what simulating broke part of the world: every broken building's pieces stay down where they are drawn (falling ones stop where they are), every felled tree stays down where it lies, every dent becomes the ground itself. | `raycast` | read-only | The first hit along a ray from `origin` in `direction` within `max_distance` (default 10000): `hit`, `entity` (0: the ground), `point`, `normal`, `distance`, `player` (true when it hits the player), `tree` {`cell` [x, z], `point`, `fallen`} when it hits a scatter tree's trunk, `surface` (what it is made of: the entity's or kit piece's surface; trees wood, characters flesh, the ground dirt). ## Adding a command

1. Write it next to the feature, with a JSON Schema for its arguments
   (`minimum`, `maximum`, `enum` and `required` keep AI calls honest) and a
   description written for the AI: what it does and anything surprising.
2. If it changes state, record a `Change` with undo and redo. If it fails
   halfway, return `CommandResult::failure`; recorded changes roll back.
3. Mark read-only commands `read_only`; they may not record changes. View
   state (window size, camera, panel layout) is not undoable, the same as
   when a person changes it by hand.
4. Test it through `CommandRegistry::execute`, and add it to
   `tools/mcp_smoke.py` if it is part of a workflow the AI will use.
